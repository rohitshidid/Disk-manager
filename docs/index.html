It measures the volume your files are actually on

On modern macOS, / is a sealed, read-only system volume holding about 12 GB. Your real data — the other few hundred gigabytes — lives on a separate APFS volume mounted at /System/Volumes/Data and shown back to you at /Users and /Applications through firmlinks.

So the usual sudo du -x / incantation measures 12 GB of files you are not allowed to touch and stops at the boundary of everything you care about. Disk Manager scans the data volume and then shows you the paths you recognise: /Users/you/Downloads, not /System/Volumes/Data/Users/you/Downloads.

Explore

List and treemap, together

Sort by any column. Dates roll up: a folder reports the newest change anywhere inside it, not the day its own entry list last shifted — which is what anyone actually means by asking when it changed.

Junk finder

The known space sinks

node_modules, Xcode DerivedData and DeviceSupport, simulator devices, .venv, __pycache__, every package-manager cache, iOS backups, Docker images. Each labelled safe, caution or danger, with what regenerating it costs.

Duplicates

Byte-identical copies

Grouped by size first, then a 64 KB head hash, then a full hash only for what still collides — so a same-size-but-different file is rejected after one small read. One click keeps the oldest of every set and trashes the rest.

Bin

An undo that outlives the app

Deleted items sit in a quarantine folder with their original paths recorded on disk. Close the app, come back tomorrow, press ⌘Z — the 107-folder batch you binned comes back as one step.

Three ways to remove something

They differ only in who ends up holding the file. Only the third one unlinks anything, and it is gated behind typing DELETE.

ActionWhere it goesHow to get it backWhen the space returns
Move to bin this app's quarantine, on the same volume ⌘Z, or Restore in the Bin tab on Purge
Move to Trash the macOS Trash Finder's “Put Back” when you empty the Trash
Delete permanently nowhere you don't immediately

“Move to bin” never unlinks: the item is renamed into a quarantine folder on the same volume. A rename within one volume is instant no matter how large the folder is, and it is exactly reversible. The status bar always shows what a purge would free and what your free space would become, which is the loop the whole app is built around — bin things as you find them, watch the number climb, purge once when it is worth it.

Guardrails, not nags

A blocklist refuses deletion outright inside SIP-protected trees, at volume roots, at your home directory itself, and anywhere inside the app's own quarantine. Beyond that: over 1 GB or 10,000 files asks for confirmation; anything outside /Users also makes you type DELETE. Deletes that need root trigger one native admin prompt per batch — never one per file — and the server itself never runs as root.

Installing

  1. Download the DMG and drag Disk Manager into Applications.
  2. Right-click it → Open → Open. The app is not signed by an identified developer, so a plain double-click is refused the first time. You only do this once.
  3. Grant Full Disk Access before your first scan — System Settings → Privacy & Security → Full Disk Access → add Disk Manager. Then quit and reopen it: the consent only applies to freshly launched processes.

Why that third step is not optional

macOS gates ~/Desktop, ~/Documents, ~/Downloads, ~/Music, ~/Pictures, ~/Movies, iCloud Drive and every app container behind separate privacy consents. A process without consent does not get a permission error when it opens one of those — the call blocks, waiting for a prompt a background process never gets to show. It waits forever, and sudo does not help, because this is consent rather than permission.

Disk Manager survives that anyway: it watches for a scan that has stopped making progress, works out which folder is responsible, confirms it before blaming it, and offers to skip it or to open the right settings pane. But a skipped folder is simply missing from your totals, so granting access is the better fix.

Or run it from source

No dependencies to install — Node 20+ and ncdu.

brew install ncdu
git clone https://github.com/rohitshidid/Disk-manager.git
cd Disk-manager
npm start          # then open http://127.0.0.1:4173

Run this way, Full Disk Access attaches to whichever terminal app launched it, not to Disk Manager — which is the single most confusing thing about the source version, and the main reason the packaged app exists.

Build the DMG yourself

npm install
npm run dist       # → release/DiskManager-arm64.dmg

That vendors ncdu and its two dylibs into the bundle, draws the icon, packages with Electron and ad-hoc signs the result.

Built to be honest about what it does not know

1.35M files in 41 MB

The filesystem is held as parallel typed arrays rather than one object per file, which would be gigabytes. Reopening reloads a cached scan in about two seconds.

Sizes match df

Disk usage, not apparent size. Hardlinked files are counted once. A subtree too large to finish measuring is marked ~ rather than quietly guessing.

Nothing leaves your Mac

The server binds to 127.0.0.1 only, requires a per-run token on every call, and rejects requests whose Host header is not localhost. There is no telemetry and no network use at all.

Refresh one folder

Re-measure the folder you are looking at instead of the whole volume — seconds instead of minutes — and every ancestor total, the treemap and the free-space projection stay correct.
