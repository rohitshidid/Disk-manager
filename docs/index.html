The problem

Your Mac won't tell you.

Storage settings shows you a bar chart of categories. It will not tell you that a folder you forgot about in 2021 is holding 40 GB, or that the same video sits in four places. Disk Manager measures every file on the volume your data actually lives on, and draws it.

🗺️

A map, and a list

A squarified treemap beside a sortable list, both showing the folder you are in. Click a block to drill in. Big things look big — that is the entire idea.

📅

Dates that mean something

A folder reports the newest change anywhere inside it, not the day its own entry list last shifted. That is what people mean when they ask when something last changed.

⚡

Refresh one folder

Re-measure the folder you are looking at instead of the whole disk — seconds instead of minutes — and every total above it stays correct.

Duplicates

Byte-identical, and proven so.

Files are grouped by size first — different sizes cannot be duplicates — then a 64 KB head hash, then a full hash only for what still collides. A same-size-but-different file is rejected after one small read, so this finishes on a real disk instead of hashing it end to end.

Every set pre-selects all but the oldest copy, on the assumption the earliest file is the original. One click clears the lot.

Nothing is erased by accident

Three ways out. Only one is final.

They differ only in who ends up holding the file. Two of them are a rename you can walk back. The third makes you type the word DELETE.

↩︎

Undo that outlives the app

Deleted items keep their original paths in a file on disk. Quit, come back tomorrow, press ⌘Z — a 107-folder batch returns as one step.

🛡️

Things it simply won't do

SIP-protected trees, volume roots, your home folder itself and its own quarantine are refused outright. Over 1 GB or outside /Users needs confirmation.

📊

Watch the number climb

The status bar always shows what a purge would free, and what your free space would become. Bin things as you find them; purge once, when it's worth it.

Getting started

Three steps, one of them optional.

Download and drag it in

Move Disk Manager into your Applications folder. Node and ncdu are inside the bundle — there is nothing else to install.

Right-click → Open → Open

The app is not signed by an identified developer, so a plain double-click is refused the first time. You only do this once.

Grant Full Disk Access, then relaunch

System Settings → Privacy & Security → Full Disk Access → add Disk Manager. Quitting and reopening matters: macOS only applies a new consent to freshly launched processes.

Why that third step isn't really optional

macOS gates Desktop, Documents, Downloads, Music, Pictures, iCloud Drive and every app container behind separate privacy consents. A process without consent does not get a permission error — the call blocks, waiting for a prompt a background process never gets to show. It waits forever, and sudo does not help, because this is consent rather than permission.

Disk Manager survives it regardless: it notices a scan that has stopped making progress, works out which folder is responsible, confirms it before blaming it, and offers to skip it. But a skipped folder is missing from your totals — so granting access is the better fix.

Or run it from source — Node 20+ and ncdu, no dependencies:

# the only external requirement
brew install ncdu
git clone https://github.com/rohitshidid/Disk-manager.git
cd Disk-manager
npm start          # then open http://127.0.0.1:4173

Under the hood

Honest about what it doesn't know.

A disk tool that guesses is worse than no disk tool. Where a number is incomplete, this one says so.

📐

Sizes match df

Disk usage, not apparent size. Hardlinked files counted once. A subtree too large to finish measuring is marked ~ rather than quietly guessed at.

🔒

Nothing leaves your Mac

The server binds to 127.0.0.1 only, requires a per-run token on every call, and refuses requests whose Host header isn't localhost. No telemetry.

🧪

Tested where it matters

33 tests covering the parser at 1-byte boundaries, the safety matrix, and the full delete → undo → redo → restore → purge cycle against a real filesystem.
